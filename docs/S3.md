# S3 provider

`packages/s3` (`@fdrive/s3`) is the third registered storage backend: any S3-compatible
bucket, self-hosted (MinIO, Garage, SeaweedFS, RustFS, Ceph RGW) or hosted (Backblaze B2,
Cloudflare R2, Hetzner Object Storage, AWS S3). Administrators add one under **System >
Storage** by an address that carries the bucket in its path, `https://minio.local:9000/media`
or `https://minio.local:9000/media/team` for a prefix. People log in with an access key ID and
secret key, link it beside an SFTPGo login, and browse, upload, download, rename, move, copy and
delete through the ordinary file UI. Deleted files go to fdrive's own recycle folder when Trash
is enabled for the row. Shares, Office, search, thumbnails and scope mapping stay unavailable
for S3 logins; the UI hides those controls and the API refuses them through capability flags.

S3 is files-only storage beside SFTPGo, not a replacement for it, and that holds for a local
MinIO as much as for a hosted bucket: the indexer reads plain files on a mounted disk, which
no S3 server's data directory is. The UI states the limit instead of leaving it to a missing
button; see [Files-only storage](STORAGE-PROVIDERS.md#files-only-storage).

Verified against a real MinIO in CI (`packages/s3/test/integration`, using the testkit's
`startMinio`) and against an in-memory protocol fake in unit tests (`src/fake/server.ts`, also
used by API tests). The other targets above are intended, not part of CI; see the
compatibility notes.

Not implemented: virtual-hosted addressing, bucket creation, IAM roles and STS session tokens,
version browsing, Object Lock, SSE-C, presigned direct downloads, multipart copy of objects
over 5 GiB, fdrive-owned shares, a remote index walker, Office admission and server-side zip.
The extension points are those in [the provider guide](STORAGE-PROVIDERS.md).

## Decisions

| Decision | Choice | Why |
| --- | --- | --- |
| Package | `packages/s3`, `@fdrive/s3`, copied from `packages/webdav` configs | The guide's step 1; protocol client, adapter and fake stay out of the API. |
| Client | `@aws-sdk/client-s3` and `@aws-sdk/lib-storage`, the versions already pinned for [backups](BACKUPS.md) | SigV4, pagination and multipart are solved and already exercised against MinIO and B2 in this repository. |
| HTTP | `@smithy/fetch-http-handler` with `customFetch: ctx.fetch` | The guide's rule that tests inject the network. The SDK's Node client accepts web-stream bodies from it, so downloads stream and multipart parts upload without buffering the whole body (up to 32 MiB per upload is held for the parts in flight). |
| Checksums | `requestChecksumCalculation` and `responseChecksumValidation` set to `WHEN_REQUIRED` | SDK defaults send CRC32 trailers that older MinIO, Garage and B2 reject. `DeleteObjects` still carries the CRC32 header the operation requires; MinIO accepts it. |
| Endpoint and bucket | `baseUrl` is `https://host[:port]/bucket[/prefix]`, always path-style | Rows are unique by `(type, baseUrl)`, so two buckets on one server are two rows. The optional prefix scopes a login to a subtree. Path-style works on every listed target. |
| Config fields | `region` (optional; read from the address for `s3.<region>.backblazeb2.com`, `s3.<region>.amazonaws.com`, R2 (`auto`) and Hetzner locations, else `us-east-1`) | SigV4 needs a region string, and B2 refuses a signature for the wrong one (`AuthorizationHeaderMalformed`). MinIO accepts any value, Garage wants its configured one. |
| Credential fields | `username` labelled "Access key ID", `password` labelled "Secret key" | Confirmation forms render `password`; `ctx.expectedUsername` fills the access key on link and unlink. The identity's `externalUsername` is the access key ID; the web lists S3 logins storage name first with the key beneath (see [Display names](STORAGE-PROVIDERS.md#display-names)). |
| `authenticate` | `ListObjectsV2` with `MaxKeys: 1` under the row's prefix | Proves the pair and list access on the scope people browse. `InvalidAccessKeyId` and `SignatureDoesNotMatch` → `unauthorized`; `AccessDenied` → `forbidden`; `NoSuchBucket`, network and 5xx → `upstream_unavailable`. |
| `probe` | Unsigned `GET` on the bucket URL; ok on 2xx, or 401/403 with an `x-amz-request-id` header or an XML `<Error>` body; `NoSuchBucket` is not ok | An S3-shaped refusal proves a reachable endpoint. MinIO answers `AccessDenied` for a missing bucket too, so the signed login check is what reports it there. Same URL checks as the other providers: http(s) only, no userinfo, no metadata hosts, 5 s timeout, 1 KiB body bound. |
| Redirects | The SDK follows nothing; a 301 `PermanentRedirect` is `upstream_unavailable` | Never sign a request for a host the server chose. |
| Retries | SDK `maxAttempts: 3`; a rejected fetch or an abort is `upstream_unavailable` | Bounded; consumed body streams are never replayed. Multipart part retries come from `lib-storage`. |
| Directories | A directory exists when a zero-byte marker `dir/` exists or any key starts with `dir/`. `mkdir` writes the marker; with `parents`, one for every missing ancestor. | Matches the MinIO and AWS consoles and rclone. Ancestor markers keep a folder alive after its last child is removed, which the Trash root relies on. |
| Modified time | `list` uses `LastModified`; `stat` and `download` prefer user metadata `mtime` (unix seconds, rclone's key); uploads write it from `modifiedAt` | Read-side interoperability with rclone is free. `setModifiedAt` stays unimplemented: it would need a self-copy with replaced metadata. |
| Content type | Set on upload from the file extension (`application/octet-stream` otherwise); `stat` returns the stored value | Other S3 clients and consoles then see the right type. |
| Capabilities | `zip` false, `setModifiedAt` false, `atomicMove` false, `trash` true, `shares` false, `office` false, `index` false, `scopeMapping` false | Move is copy plus delete per object; the API's caution copy for folder moves applies. |
| Trash | `"move"` strategy | No recycle bin in S3. The API storage factory moves deleted objects into the configured folder itself (`withMoveToTrash`); see [Trash](TRASH.md). |
| Real backend in CI | MinIO, the image the backup suite pins, through `@fdrive/testkit`'s `startMinio` | One bucket, a read-write user and a read-only user created with the `mc` client the image ships. |

## Protocol mapping

Paths are provider-relative, normalized with core `normalizePath` at the adapter boundary. A
file at `/a/b.txt` under prefix `p` is the key `p/a/b.txt`; the directory `/a` is the key
prefix `p/a/`. Keys the server returns are accepted only when they denote one direct child
with a name fdrive can show as a path segment; anything else is ignored, never followed.

| Port method | Request | Notes |
| --- | --- | --- |
| `list` | `ListObjectsV2` with `Prefix: dir/`, `Delimiter: /`, continuation tokens | `CommonPrefixes` are directories, `Contents` files; the directory's own marker is dropped; a folder wins over a same-named object. Empty answer for a non-root path: `bad_request` when a file sits at the path, else `not_found`. Capped at 100 000 entries → `internal`. |
| `stat` | `HeadObject` on `key`; on 404, `ListObjectsV2` `MaxKeys: 1` under `key/` | The root is always a directory. |
| `statFile` | `stat` | Directory → `bad_request`. |
| `probeDirectoryRead` | `ListObjectsV2` `MaxKeys: 1` | A live listing, not a stat. |
| `download` | `GetObject` with `Range` | S3 has no `If-Range`: an ETag validator becomes `If-Match`, a date `If-Unmodified-Since`, and a 412 answer is retried once as an unconditional full read. An unparsable validator sends the whole body. Caller's `AbortSignal` only. |
| `upload` | `PutObject` for byte arrays; `lib-storage` `Upload` for streams (8 MiB parts, 4 in flight, parts aborted on cancel; the backup destination's settings) | `overwrite: false` is a `HeadObject` pre-check, racy and documented as such; conditional `If-None-Match` writes are not used because targets differ. `mkdirParents` needs no request. |
| `mkdir` | `PutObject` of an empty `dir/` with `application/x-directory` | A file at any level: `conflict`. Without `parents`, an existing folder: `conflict`, and a missing parent: `not_found` (a file there: `bad_request`), as WebDAV answers. |
| `move` | File: `CopyObject` then `DeleteObject`. Directory: list every key under the prefix, copy each (4 in flight), then `DeleteObjects` in batches of 1000 | An existing target is replaced: a folder there loses every object first, so nothing of it survives under the new one. Non-atomic: a failure leaves the copied objects (or an emptied target) and reports the error. The root, a target inside the source and objects over 5 GiB are refused before anything is touched. |
| `copy` | As `move` without the deletes | Same bounds. |
| `deleteFile` | `HeadObject` then `DeleteObject` | A folder at the path answers `bad_request`; `DeleteObject` on a missing key is 204, so the head supplies `not_found`. |
| `deleteDir` | List every key under the prefix, `DeleteObjects` in batches of 1000 | Refuses a file with `bad_request` and the root outright. Nothing under the prefix and no marker → `not_found`. A per-key refusal in the batch answer is `forbidden`. |

Error mapping (SDK error name or status → `StorageError`): `NoSuchKey`, `NotFound`,
`NoSuchUpload`, 404 → `not_found`; `AccessDenied` → `forbidden`; `InvalidAccessKeyId`,
`SignatureDoesNotMatch`, `ExpiredToken` → `unauthorized`; `PreconditionFailed`,
`BucketNotEmpty`, 409, 412 → `conflict`; `EntityTooLarge`, 413 → `payload_too_large`;
`SlowDown`, `ServiceUnavailable`, 429 → `rate_limited`; `InvalidRequest`, `InvalidArgument`,
`InvalidRange`, `MalformedXML`, 400, 416 → `bad_request`; `NoSuchBucket`, `PermanentRedirect`,
`InternalError`, aborts, timeouts, rejected fetches, 3xx, 5xx → `upstream_unavailable`;
anything else `internal`. Details keep the code, status and a 500-character message excerpt.
Signature failures carry no server message at all: MinIO echoes the string-to-sign, which
includes the access key ID.

Bounds: 120 s per request attempt, from the first request byte to the response headers (the
backup destination's value, so an 8 MiB part fits on a slow uplink); list pages of 1000; 100 000
keys per directory operation; probe bodies 1 KiB.

## Compatibility notes

| Target | Verified | Notes |
| --- | --- | --- |
| MinIO | CI container (`RELEASE.2025-09-07`) | Anonymous probes cannot tell a missing bucket from a private one. The built-in `readonly` policy grants `GetObject` without `ListBucket`, so such a login can read known paths but not browse. `mtime` metadata, multipart and CRC32 `DeleteObjects` all round-trip. |
| Garage, SeaweedFS, RustFS, Ceph RGW | Not yet | Intended self-hosted targets. Garage wants its configured region; the others accept any. Record deviations here when verified. |
| Backblaze B2, Cloudflare R2, Hetzner, AWS S3 | Not yet | The region is read from the address; the field overrides it. The backup destination already talks to B2 with the same client settings. |

A target that fails the conformance suite is documented here, not silently supported.

## Known limitations

- **Folder moves and deletes cost one request per object**, and moving a folder to Trash is
  a full copy of its contents. The 100 000-key bound turns a runaway folder into a clear
  error rather than an hour of requests.
- **`overwrite: false` is a pre-check.** Two writers racing for the same new name can both
  succeed; the second wins.
- **A move or copy onto an existing folder empties that folder first.** That is what the port
  promises, and a failure after the deletes leaves the target emptied; callers that must keep
  both sides pre-check with `overwrite: false`.
- **Objects over 5 GiB** cannot be copied or moved through fdrive (`payload_too_large`);
  `UploadPartCopy` is not implemented.
- **`stat` costs up to two round trips** for a directory. Acceptable for browsing.
- **Lifecycle rule for aborted uploads.** fdrive aborts a cancelled multipart upload, but a
  crash between parts leaves them on the server; buckets should carry the usual
  abort-incomplete-multipart lifecycle rule.
