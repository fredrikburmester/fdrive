# P5 scope consumers (queued after engine and provider binding)

Implements P5-SCOPES.md using the reviewed resolver. Split HTTP/Office wiring and MCP into separately isolated chunks; exact exported resolver types are pinned when the engine reports. No worker assigned by this document.

## HTTP, Office and events chunk

Ownership: apps/api/src/composition.ts, search/**, thumbs/**, new scoping/routes.ts/tests, accounts/types.ts and narrow views wiring, office/{types,auth,service,write-file,registry-events}.ts and tests, events/indexer-listener.ts/tests. Narrow contracts search partial flag and scope client additions only after the engine releases contracts. Existing provider-binding auth files are prerequisites, not part of this chunk. To keep the required SearchService interface compiling without an unsafe compatibility fallback, this chunk also owns the narrow MCP runSearch call-site and its dependency/test fixture adaptation. Other MCP tools stay for the following chunk. MCP implementation starts only after this transfer, never concurrently in handlers.ts.

SearchServiceInput receives explicit scopes and a request-local read authorizer; remove its homeTemplate/username authorization fallback. Search status becomes identity-specific. Resolve identity and immutable storage once at the request boundary. Do not accept user-supplied scope arrays. Filter mapped candidates by exact round trip and live read before making hits, content snippets, thumbnail flags or derived folders. Apply limits after inaccessible candidates are removed, within the existing bounded signal fanout. Do not report inaccessible candidates in totals. Folder results additionally require directory access. Preserve semantic degraded semantics; optional partial reports omitted/unavailable checks separately.

Scope GET is cookie-owned identity; PUT additionally admin + CSRF. Validate before persisting. Login/link verification is best effort status computation, never a reason to deny ordinary storage login solely because indexer is down. A request arriving after configuration changes must use new mappings. Admin editing scopes does not alter upstream permissions. Native thumbnails require the same owned identity, live content read, verified scope and private,no-store.

Office actor carries resolved configured mappings, independent of indexer availability. Resolve before the provider write transaction; keep fresh registry-row lookup inside transaction from the queued-save repair. Callback path must round trip under this actor's current configured mappings. Preserve UUID across real renames; no credential/pool/config fetch inside write transaction. Wrong provider/root/override mapping denies. Metadata-generated registry updates and indexer events use the same configured mappings. Index events must not broadcast hidden/shadowed paths: live-check created/changed destinations; move/delete may update existing owned metadata but must not reveal an unverified destination. Never reassign an old provider's event to a newly configured provider merely because root names match.

Tests include authenticated search, cross-account search, native identity thumbnail URLs, admin/nonadmin scope responses, wrong template, shadowed same-name files, list-only/download-denied files, cache/config races and Office rename/write regressions. Real isolated SFTPGo/indexer test verifies two identities and virtual mount mappings. Full API/contracts gates and root integrations after transfer.

## MCP chunk

Ownership: apps/api/src/mcp/** excluding unchanged indexer client; narrow composition MCP dependency wiring reconciled after HTTP chunk; packages/db/src/repos/index-queries.ts/tests only if an explicit authorized-ID aggregate query is needed. No changes to HTTP search or Office files. Each tool uses verified scopes and one bounded request-local authorizer, never username-template fallback.

Filter file_info, find_files, duplicates, similar_files, folder_overview and index_stats before returning names, hashes, text status, snippets or aggregates. Live extraction requires download permission before invoking the internal indexer. Similar-file source also requires read. Duplicate group count/wasted bytes derive only from authorized paths, and groups with fewer than two authorized copies disappear. find_files cannot return an unfiltered SQL total as total_matches. Folder overview must not add bytes before path/read filtering. recent_moves requires both mappings to round trip and destination authorization; hidden source paths must not be disclosed. Existing actual storage list/mkdir/move remain native-authorized and useful when indexing is unavailable.

Aggregate tools must remain bounded and truthful: authorize at most2000 candidate files per request, six concurrent checks. Return counts for the authorized examined subset with partial:true whenever capped, denied or unavailable; never present them as exact whole-index totals. Chunk counts, if retained, must use only authorized file IDs (bounded SQL parameters), not all scoped rows. Avoid buffering downloaded bodies; open/cancel probes only. No global positive read-permission cache. Tests require exact denied-file exclusion from every aggregate and all tool variants, native token principal provider binding, literal percent paths and bounded fanout. Preserve tool names and useful response fields; explain partial semantics in tool descriptions.
