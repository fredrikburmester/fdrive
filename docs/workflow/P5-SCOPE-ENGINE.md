# P5 scope engine (queued, independent of provider binding wiring)

Implements the resolver and permission-filter foundation of P5-SCOPES.md. Read that full architecture first. This chunk deliberately owns no composition/auth/search route files, allowing provider-binding work in parallel. Parent will integrate and assign consumer wiring separately.

## Ownership and fixed interfaces

New apps/api/src/scoping/** only; new packages/contracts/src/scopes.ts/scopes.test.ts and narrow index.ts/routes.ts/routes.test.ts additions for the identity scope endpoint. No other production files, schema or dependencies. Colocated pure/unit tests and self-contained fixture helpers. Existing indexer directory client is complete and must be reused. Existing core mappings are reused, wrapped with explicit round-trip filtering rather than silently changing all callers during this chunk.

Export createScopeResolver(deps) with configuredMappings(identity), verifiedIndexScopes(identity), status(identity, isAdmin), setOverrides(identity, scopes). Identity is the existing DB identity type. Configured mapping resolution must return an empty mapping or a typed unavailable reason on no connection/provider mismatch; never substitute another identity. Storage dependency is async storageForIdentity(identity): Promise<StorageProvider>, already bound to that provider by the later composition wiring. Other dependencies: provider/settings repos, connection store, configured root descriptors, indexer directory client, clock. Keep exact dependency interfaces narrow and report exports before consumer wiring.

GET/PUT contract path /api/v1/account/identities/:id/scope. PUT strict {scopes:[{rootName,fsPrefix,virtualPrefix}]} max32; [] resets override. Canonical UUID path. Response discriminated on administrator visibility: common status (available/unavailable), reason enum, usesOverride, virtualPrefixes, and warning text; administrator additionally gets configured roots and full mappings. No fsPrefix/root-specific disk paths in nonadmin response. Route authorization is a later chunk; service must not represent callers as administrators implicitly.

configuredMappings reads current connection/template and owned identity settings, validates provider UUID/type/exact baseURL, returns trusted mappings even when indexer is down. verifiedIndexScopes performs bounded real SFTP/list versus indexer directory consistency checks and returns only verified mapping data. Verify every configured mapping's mount directory, exclude virtual mount entries represented by more-specific mappings, allow extra hidden physical entries. Any mismatch/overflow/unavailable service denies index-backed access for that identity with a useful typed reason. Never claim matching names prove storage identity.

Cache verification <=30s, at most1000 identities; exact key includes identity/provider/current template/roots/overrides. Re-read configuration before cache lookup. Coalesce matching work; new configuration cannot reuse old in-flight result. Eviction cannot turn failure into a grant; remove failed promises. setOverrides validates and persists/reset then invalidates relevant cache. Explicit expiry tests with injected clock, no sleeps.

Export a pure roundTripVirtualPath(scopes,rootName,fsPath) returning string|null only when virtual->filesystem returns the same normalized root/path. Export a bounded per-request live-read authorization helper: mapped file content requires storage.download open then body cancellation; directories require list. Reuse checks for duplicate references within one request, cap concurrent probes (default6), distinguish denied/missing from upstream unavailability without exposing raw paths. No global positive path-grant cache. This helper must not buffer files or convert a successful stat into read authorization.

Mapping JSON paths are already decoded strings. Preserve literal percent sequences such as a directory named `%20`; never call decodeURIComponent on them. Reject actual dot/dot-dot segments, backslashes, NUL/control characters, duplicate/trailing separators and noncanonical paths. Encode transport components once through the established clients; tests distinguish literal percent names from traversal.
