# P5 share management and public pages (queued)

Read stable reviewed P5-SHARES-API contracts before implementation. Primary assigns after account web releases shared browser/sidebar paths. No new dependencies/handmade primitives; existing shadcn UI, tokens, field descriptions.

## User flows

Authenticated Shares page/sidebar location lists current login's managed links, name, read/upload-only, password indicator, expiry/usage and copy-link/edit/revoke. File/folder context menu Share opens creation with selected canonical paths. Default name selected basename, read/download link; upload-only only one directory, no mixed write/read scope. Multi-file read link is ZIP archive. Fields: name, optional description/password/expiry/download limit with descriptions; blank password on create means none, on edit keep existing by default with explicit Change/Remove controls (don't accidentally clear). Secret only local transient state, cleared on close/success; don't retain mutation variables. Revoke confirms link only, explains source files remain. Use scoped client captured per action, generation guards from account work; identity switch clears stale links/dialog context.

Public /s/[id] outside authenticated shell, accessible signed-out, fdrive branding and simple card/list. Server/API share UUID only, no owner/private upstream location. Metadata name/description, expiry/limit messages; fileName basename for single-file previews/download extension, never full path. Password form uses setSharePassword then public request; encrypted HttpOnly cookie is merely stored input, not proof password accepted. Directory entries request verifies; read-only file/archive explicit download verifies; upload-only explicit upload verifies. Show useful upstream password/errors and let replace password. No fake probe downloads that consume quota. Password never URL/localStorage/console. Display quota note: previews/download requests count under upstream share limits.

Directory browser uses share-relative paths, segment-safe navigation and breadcrumbs; files can preview/download; root archive action. Single-file view shows file and Download; archive view shows Download ZIP only, no owner listing fallback. Upload-only page shows drop/select-files queue, per-file progress/cancel/retry and results; single basenames only (no folder drop), no listing or previews. Use XHR upload progress to public upload URL, cookie same-origin, standard CSRF header; abort supported. Never attach viewer account identity header or owner credentials to public calls.

## Streaming and safe preview

Downloads use native same-origin URLs with encrypted share cookie, no buffering of large files. To surface rejected native downloads, a same-origin hidden named iframe may target attachment response; on error JSON navigation, read only the known API error response and report its sanitized message. Never render error as HTML. Successful attachment downloads stay native; no full-file blobs merely to save. Keep product implementation details invisible.

Reuse existing image/audio/video viewers with public download URL where browser media supports attachment and Range. PDF/text/code/markdown preview may fetch bounded content only: enforce32MiB PDF/media blob cap and1MiB text cap, abort overflow, show Download instead. Revoke object URLs on close; do not render untrusted HTML/SVG inline on app origin. Existing React text/markdown escaping retained, PDF sandbox or safe blob viewer. Restrict preview by known file extension/content type, unsupported => download. Raw file responses always attachment/nosniff. Browser media errors should offer password retry or generic unavailable message; metadata refresh can explain expired/exhausted links. No protected file-byte caching across share/password changes.
