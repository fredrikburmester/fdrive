# P5-SHARES-API

Phase5 public share proxy and authenticated management. Primary-defined architecture. Worker owns implementation/tests, no delegation, Git mutation or stash.

## Ownership

apps/api/src/shares/** and apps/api/test/integration/shares-sftp.test.ts; composition.ts only share wiring; packages/contracts/src/shares.ts/tests, client.ts/tests, routes.ts/tests,index.ts; packages/sftpgo/src public-share client/types/shares/fake and corresponding tests/integration contract suite. No DB/web/config/office changes without parent agreement. Existing ShareRepo integrated. No new dependencies.

## Management

Cookie session+CSRF only (reject Authorization like account mutations). Selected identity from principal, revalidate ownership/provider against configured connection each operation. Resolve identity JWT through token source. Never use owner JWT on public bytes/list/uploads. Routes /api/v1/shares GET/POST, /shares/:id GET/PATCH/DELETE; id always fdrive UUID. List only fdrive-managed shares owned by selected identity, refresh upstream metadata; missing upstream can be removed locally, unavailable upstream explicit error. Strict bounded inputs name1..255, description<=2048, canonical paths1..1000, scope read|write, expiry ISO|null, maxDownloads int>=0, optional password<=1024. Password undefined on PATCH preserves; empty clears; nonempty sets. Existing SFTPGo client correctly uses [**redacted**] on update; real test prove. PATCH partial merges with current upstream metadata before complete upstream update. Never accept allowFrom/IP rules in this first UI/API because public traffic exits fdrive and upstream cannot infer viewer IP. Return owner metadata incl paths and fdrive public path /s/:uuid, never upstream IDs, encrypted secrets, owner JWT or raw upstream errors.

Create upstream first, fetch resulting metadata, persist via ShareRepo upsert. If persistence fails compensate remove upstream; sanitized errors and explicit compensation failure log without secret. Update upstream then mirror; failure must surface and next GET reconciles. Delete upstream then local; upstream404 treated deleted. No owner-data mutation on share revocation. Real upstream source of truth for permission/expiry/password/usage.

## Public API and password envelope

/api/v1/public/shares/:id GET returns minimal public metadata: name, description, scope, layout single-file|directory|archive, hasPassword, credentialPresent, expiresAt, maxDownloads, usedDownloads, unavailableReason expired|limit|null. Do not disclose owner/provider/root/paths/upstream IDs. Shape can be pinned in contracts and reported before web starts. Owner get permitted for metadata only; derive layout using owner stat ONLY during management creation or public metadata (stat first; list only directory). Multi-path always archive. Missing/deleted share404. Public metadata is intentionally visible to bearer of unguessable link even before password, file content never is.

POST /.../:id/credentials {password:string<=1024} stores a purpose-separated encrypted HttpOnly cookie, scoped exact /api/v1/public/shares/:uuid path, SameSite=Lax, Secure per existing config; maxAge1hour. Use HKDF-SHA256 master key info fdrive-public-share-credentials-v1 and existing seal/open AAD share UUID. Payload password+expiry+share ID; strict bounded envelope/canonical base64url; tamper/expiry treated absent, never log decrypted values. This endpoint DOES NOT claim password verified: directory listing or explicit download/upload verifies with upstream. No fake probe download consumes quota. DELETE credentials clears cookie. Cookie only encrypted in browser, password never DB, localStorage or URL. CSRF same-origin guard retained for public writes.

GET /.../:id/entries?path=/ relative canonical shared path; directory read shares only; forward publicShare.list with cookie password. GET /.../:id/download?path=/ for single-file raw or directory child download; Range/If-Range supported. GET /.../:id/archive for ZIP; write-only has no read endpoints. PUT /.../:id/upload?path=/filename streams browser body to publicShare.upload; write-only only, filename/path strictcanonical relative within shared root, reject traversal encoded/backslash/dot segments (one decode only). Do not implement user-credential fallback. Add SftpgoPublicShareApi.downloadFile(options) for GET /api/v2/shares/:id?compress=false (upstream /files only supports directory share), and optional AbortSignal for upload/zip. Keep source public behavior consistent fake and real.

Every proxy request reloads upstream metadata and forwards actual password via Basic to SFTPGo public endpoint; forwarding not metadata flag enforces revoked password/expiry/usage. SFTPGo v2.7.5 checks usability before password, so generic400 is never auth success. Translate to sanitized useful password/expiry/limit/error result, use upstream metadata for known expiry/limit. Enforce read/write shape locally too. Stream with backpressure and request abort; preserve206/content-range/content-length/content-type/lastmodified, attachment disposition safe filename; nosniff/no-store/referrer-policy no-referrer. Prevent active HTML/SVG from executing on app origin: attachment always for download, later web safe viewers via blob or sandbox. Never buffer whole download/upload. Public paths never passed to owner user API.

Rate limit public endpoint by trusted extracted client IP + share ID, bounded in-memory map TTL, default120 requests/minute with stricter10 credential attempts/minute. Public endpoints must not authenticate viewer session. No forwarded-IP trust expansion. Same-origin cookie envelope is convenience only; upstream remains authority. Account unlink preserves share ownership via identity UUID, revocation upstream immediate.

Sources verified: SFTPGo v2.7.5 internal/httpd/api_shares.go (getBrowsableSharedPath, checkPublicShare, downloadSharedFile, downloadShare; source github.com/drakkan/sftpgo/blob/v2.7.5/internal/httpd/api_shares.go). Single-file root compress=false supports Range; multi-path ZIP only. Do not assume fake behavior when source differs.
