# P5 scope consistency and verification (queued)

Primary architectural decisions; implementation split after shared composition/contracts ownership clears.

PLAN's current claim that comparing names guarantees no wrong-root disclosure is false: different roots can have identical names. Correct the contract: administrator-controlled root mappings are an authorization boundary; login-time comparison detects obvious mapping errors, not cryptographic proof of identical storage. Unprivileged users never choose filesystem/index prefixes. Live SFTP read checks are additionally required before returning cached file content/previews; listing/stat alone does not prove download permission. Neither check repairs a deliberately wrong trusted mapping.

## Interfaces and behavior

One configured mapping resolver per identity: provider must equal configured SFTPGo provider, template from CURRENT connection store, plus per-identity overrides from settings key identity_scope:<canonicalUUID>. Override value {version:1, scopes:[{rootName,fsPrefix,virtualPrefix}]}; max32, strict known roots and canonical paths, no duplicates virtualPrefix, no encoded/traversal/backslash ambiguity. Use existing core scopesFor/toFsPath/toVirtualPath, segment-aware longest prefix. Empty candidate roots => index unavailable, ordinary SFTP still available.

Separate configuredMappings(identity) from verifiedIndexScopes(identity): office stable UUID location uses trusted configured mappings (does not depend on index contents/indexer uptime); every index-derived response uses verifiedIndexScopes. Both share exactly the same mapping data and changes. Metadata event mapping uses configured mappings, but index-driven client notifications must not send unauthorized content/paths.

GET /api/v1/account/identities/:id/scope: cookie-owned identity, mapping/status/warning; no other account access. PUT same path: cookie+CSRF AND fdrive admin AND owned identity; {scopes:[...]} stores overrides; [] removes overrides/template applies. No API tokens for configuration. Nonadmin can see only virtual mapping/status, not physical prefixes; admin sees full mapping. No user-provided candidate mapping via query. Config changes invalidate verification immediately; provider changes bind through immutable provider ID.

Internal indexer directory listing: internal-network-only like existing indexer routes (no secret exists today), configured root name + strict relative path; resolve within root, reject symlink escapes, list names/kinds only (no content), bounded10000 items and overflow flag. Never arbitrary OS absolute paths. TS indexer client shares contract. Verification compares SFTP visible entries with actual disk mapping directory, excluding virtual mount points represented by more-specific overrides. Require visible entry names/kinds all present; extra disk entries permitted for SFTP hidden filters. Empty visible listing can pass consistency but is not identity proof; trusted admin mapping remains boundary. Any mismatch/unreachable/overflow denies index-backed features with useful status. Verify on login/link and lazily on first index request; cached result <=30sec keyed identity/provider/current template/exact overrides. In-flight coalescing and bounded cache. Request after mapping change cannot reuse old result. Per-path permission denial must not be cached as grant.

Every search/duplicates/similar/overview/thumbnail/live extraction/MCP endpoint gets explicit verified scopes, never silently fallback template. Account-wide search same resolver. Snapshot content/snippets/thumbnails require storage.download authorization (open/cancel or stream when actual output); directories require list. Bound concurrent read probes, reuse per-request checks for duplicates across sections. Authorization failures omit inaccessible rows/mark partial without leaking snippets. Read endpoints must honor identity header/native identity query ownership. Streaming content can retain standard read-authorization timing semantics; mapping configuration and credential changes invalidate caches.

Apply dynamic configured mappings to office registry events and canonical paths; preserve stable IDs on rename, never derive office IDs from index rows. Do not reset registry on index clear. Changes to scope mapping are explicit admin configuration; old UUID paths no longer within scope must deny callbacks.

## Review refinements

- Mapping round trips are mandatory: for every index/event filesystem reference, toVirtualPath followed by toFsPath must equal the original root/path. A virtual override such as /shared must hide the home root's physical /alice/shared subtree; otherwise a valid live read of the override could authorize cached bytes from the shadowed home location. Filter shadowed results/events before emitting any content. Tests cover matching filenames in both physical locations.
- Thumbnail HTTP caching must not bypass live permission checks after mapping/permission changes: replace private,max-age=86400 with private,no-store, or revalidate every request and authorize before304. Prefer no-store for this chunk. Preserve identity-qualified browser URLs.
- Full settings UI for mappings is part of this chunk's follow-up web task: identity card status, admin mapping editor with root/physical prefix/virtual prefix descriptions and warning that operator mapping grants access to cached content. Nonadmin sees virtual paths/status only.

## Consumer wiring follow-up

The independent engine/contracts chunk is P5-SCOPE-ENGINE.md. Consumer wiring follows both it and provider binding. Search service must require explicit verified scopes plus request-local live-read authorization; remove username-template fallback from search/duplicates/similar/overview/thumbnail/extraction and MCP. Configured mappings remain separate for Office stable IDs and metadata/event rename mapping.
