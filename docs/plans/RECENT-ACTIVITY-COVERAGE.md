Implemented from `origin/main` `26bc01e`, 2026-09-14; reconciled against `484f8a91` on
2026-09-19. Rows marked **Since 26bc01e** changed with main. The inventory below records
producer boundaries and acceptance obligations; the evidence ledger distinguishes direct history tests
from existing protocol coverage and supported runtime limits.
Use exact [taxonomy names](RECENT-ACTIVITY-EVENTS.md) and [schema/API boundaries](RECENT-ACTIVITY-SCHEMA.md).
S1–S4 refer to the separate definitions of done in [the plan](RECENT-ACTIVITY.md).

New file commands require a producer row and a history regression before release.
Every applicable case asserts owner account, captured storage identity, subject continuity,
action/source/evidence, outcome and safe before/after detail. One producer hook is not proof
that every path through that producer has been exercised.

## Explicit exclusions and platform limits

| Surface | Classification and evidence required |
| --- | --- |
| Folder visits, automatic lists/stats, polling, HEAD, thumbnails, prefetch, permission probes | Excluded by taxonomy; tests assert zero personal events. Explicit inspect/read/download gestures have separate admission context. |
| System settings/maintenance, automatic indexing/OCR | Keep the actorless admin `system_events` and worker logs. They never become the personal history store or a forged user save. Unexpected authorized file changes can yield a private observation. |
| Public share recipient traffic | No authenticated owner action. Do not attribute a recipient download/upload to the creator. A resulting change can be a private Unknown observation for an already tracked journey. |
| Cached/offline native human opens | Not established by the current API/OS signals; do not claim coverage. Actual supported hydration and write operations are covered. |
| WebDAV and S3 external watcher | No source exists for either. Refresh-only reconciliation is the supported boundary. |
| `/.fdrive-desktop` bookkeeping folder **Since 26bc01e** | The Mac app's own root-level folder, hidden from `fs/list` but real on storage. Excluded at observer admission like the trash folder; tests assert that its churn produces zero personal events. A deliberate user action on a path inside it is still that user's action. |
| SFTPGo roots absent/inotify disabled or LISTEN gap | No exhaustive watcher coverage; bounded refresh comparison and explicit observation gaps. Core fdrive actions remain recorded without indexing. |
| Conversion or other future commands | Add a taxonomy/inventory row and producer regression when the command exists; do not claim current coverage for an unimplemented operation. |

| Read volume | S2 recents; all S3 reads | Durable window/count/receipt rules from taxonomy; 1,000 repeated gestures and replay, mutation boundary, restart before sealing and late-report rejection. |

| Scale | S4 only | Million-event multi-account fixture, 1,000-file batch, query plans, bounded stat/hash calls, documented latency budget before qualification. Earlier slices use their smaller acceptance fixtures. |

Broad application or workflow passes alone do not establish producer coverage or live-provider behavior.
